# 调研：实时语音模型选型（价格 / API / 跑分）

> 调研日期：2026-08（以百炼控制台实时价格为准，本文快照可能过时）

## 结论（TL;DR）

**首选 `qwen-audio-3.0-realtime-plus`**：
- 跑分：阿里官方口径——**Artificial Analysis Speech-to-Speech 子项综合排名第一**（实时双工语音模型）
- 能力：端到端音频进/出、**Function Calling 支持**（实时 WebSocket 模式下 Qwen-Omni 系列反而**不支持** FC，这是 audio 系列的关键优势）、VAD、打断
- 个人日用的成本完全可接受：10 分钟对话 ≈ **¥0.7~1**

## 百炼可选的语音转语音（S2S）模型

| 模型 | 定位 | 协议 | Function Calling | 备注 |
|---|---|---|---|---|
| `qwen-audio-3.0-realtime-plus` | 高能力实时对话（对位 GPT Realtime / Gemini Live） | WebSocket / WebRTC / AOQ | ✅ | **本项目首选** |
| `qwen-audio-3.0-realtime-flash` | 成本敏感对话（对位 gpt-4o-mini-realtime） | 同上 | ✅ | 便宜约 1/3，极速版更注重响应速度，可作降级选项 |
| `qwen3.5-omni-plus-realtime` | 全模态（音频+图片+视频输入） | WS / WebRTC | ⚠️ 实时模式不支持 | 支持**联网搜索**；价格约为 plus 的 2 倍 |
| `qwen3.5-livetranslate-flash-realtime` | 同传/翻译 | WebSocket | ❌ | 60 种语言互译 |
| `qwen3-omni-flash`（HTTP 文件模式） | 视频分析/批量打标 | HTTP | ✅ | 支持思考模式（思考模式不生成语音） |

注意（官方文档明确）：
- **Qwen-Audio Realtime 不支持联网搜索、不支持思考模式** → 联网调研能力要由我们自己的工具（搜索 API + Function Calling）补齐，这正好契合 agent 外壳架构
- **plus 和 flash 输入模态都只有 Audio + Text，看不懂图片** → 视觉能力两条路：①换 omni 系列（贵一倍且实时模式无 FC）；②保持 audio 模型 + 外挂"看图"工具（调 qwen-vl 系列 HTTP 接口，结果以文本注入语音会话）——后者更契合外壳架构且成本可控
- 上下文：40960 tokens；音频上下文保留约 300 秒 / 最多 50 个音频轮次
- 限流（华北2-北京）：60 RPM / 100,000 TPM

## 价格（华北2-北京，原价，元/百万 tokens）

| 计费项 | plus（北京/新加坡） | flash（北京/新加坡） |
|---|---|---|
| 输入：音频 | 40 / 47.96 | 30 / 33.72 |
| 输入：文本 | 5 / 6.0 | 3 / 3.37 |
| 输出：文本 | 40 / 47.96 | 30 / 33.72 |
| 输出：音频（输出文本不重复计费） | 150 / 179.86 | 100 / 112.41 |

**音频 token 换算：12.5 tokens/秒**（1 分钟音频 = 750 tokens；不足 1 秒按 1 秒计）。
即 plus：每分钟音频输入 ≈ ¥0.03，每分钟音频输出 ≈ ¥0.11。

**成本估算**（10 分钟对话，用户说 5 分钟、模型说 5 分钟）：
- 音频输入 3750 tok × ¥40/M ≈ ¥0.15
- 音频输出 3750 tok × ¥150/M ≈ ¥0.56
- 合计 ≈ **¥0.7**（+ 系统提示/工具调用/历史上下文的文本 token，粗算 10 分钟 ¥1 以内）
- 每天用 30 分钟 ≈ ¥2~3/天 ≈ **¥60~90/月**

**海外市场售价 $25~30/月的 COGS 估算**（新加坡区价格，用户每天用 30 分钟：15 分钟输入 + 15 分钟输出）：
- plus：11.25k tok × ¥48/M + 11.25k tok × ¥180/M ≈ ¥2.6/天 ≈ **¥78/月 ≈ $11/月**
- flash：≈ ¥1.6/天 ≈ **¥49/月 ≈ $7/月**
- 结论：$25~30 定价下语音模型成本占比约 25~45%，毛利空间健康；但**海外用户到新加坡/北京机房的网络延迟**（尤其欧美用户 +100~300ms）是体验风险，需实测

成本注意点（来自实战经验贴）：
- 客户端持续推流时**静音也可能计费**；打断前已生成的音频**可能照收**——需实测
- 长会话的历史上下文会作为后续轮次的输入重复计费 → 外壳要做好上下文裁剪
- 需要设置会话时长上限、预算告警

## API 要点（Qwen-Audio Realtime WebSocket）

- 接入：`wss://dashscope.aliyuncs.com/api-ws/v1/realtime?model=<模型名>`，事件驱动 JSON 协议
- 客户端事件：`session.update`（配置音色/VAD/工具）、`input_audio_buffer.append`（推 PCM 音频）等
- 服务端事件：VAD 检测、`response.audio.delta`（流式音频输出）、Function Calling 回调等
- 音频格式：PCM16，输入 16kHz / 输出 24kHz（需在接入时确认）
- 认证：`Authorization: Bearer $DASHSCOPE_API_KEY`
- 详细事件清单见官方文档（改协议代码前必读，不要凭记忆写字段名）

### Agentic / 综合 Index / 延迟 / 成本

- **Agentic（τ-Voice）**：Grok Voice Think Fast 2.0 第一（56.5%），**Plus 第二（54.6%）**，GPT-Realtime-2.1 High 第三（45.7%），Flash 较弱（35.9%）
- **综合 Index 全球第一：Plus（84.1%）**；Grok 2.0（82.9%）第二；GPT-Realtime-2.1 High（79.1%）第三；Flash 第五（76.3%）
- **首音延迟**：Plus 1.54s / Flash 1.55s —— 中规中矩；最快是 Deepslate Opal 0.44s、Grok 2.0 0.70s。⚠️ 有第三方实测 Plus 平均首音达 4.02s，需在目标市场实测
- **成本**：Plus 是全球主流 S2S 模型中**最便宜**的（输入音频约 $0.03/小时，OpenAI 同级 $1.15/小时，差 38 倍）

结论：**Plus 是推理/对话质量/综合三榜第一 + 成本倒数第一，短板是延迟和 Flash 的 agentic 得分**。对'知识问答 + 调研'场景（重推理与对话质量，对亚秒级延迟不敏感）是全球最优选。

开源对照：Qwen3-Omni-30B-A3B（Apache-2.0）在 36 个音视频 benchmark 中 22 项 SOTA——未来若自托管可备选，现阶段 API 成本低，没必要

## 视觉模型选型（看图工具，2026-08 定案）

语音模型（plus/flash）都看不懂图片 → 后端外挂"看图"工具，调用 HTTP 视觉模型，结果以文本注入语音会话。

**已定：`qwen3.7-flash`**
- 定位：轻量低成本档（对位 Gemini 3.1 Flash / GPT-5.4-mini），官方称"接近旗舰效果"
- 输入：文本/图像/视频（单图最高 1600 万像素；视频最长 2 小时——未来"看视频"工具也复用它）
- 价格（北京）：**输入 ¥0.2 / 输出 ¥0.8 每百万 tokens** → 识别一张图约 ¥0.001 级别，成本可忽略
- 支持 Function Calling、结构化输出（JSON）、内置工具；1M 上下文
- 与语音模型同一个 `DASHSCOPE_API_KEY`、OpenAI 兼容 HTTP 接口 → 零额外接入成本

**升级档：`qwen3.7-plus`**（平衡旗舰，复杂图表/文档理解不达标时切换）。OCR 重度场景另有专用 `qwen3.5-ocr`。

调用节奏建议：看图工具同步调用但设超时（~8s），语音侧先给口头确认（"我看一下这张图"），避免对话冷场。VL prompt 强制 150 字以内口语摘要（生成时间是延迟的最大变量）。

**速度横测**（Crazyrouter 2026-06 六模型同任务实测，注意经路由器有额外开销，仅作方向参考）：gpt-4.1-mini 平均 1.49s 最快；gemini-2.5-flash-lite 2.62s；gpt-4.1-nano 2.86s；qwen3-vl-flash 3.82s。⚠️ gemini-2.5-flash 经该路由 0/6 识别失败（HTTP 200 但没"看到"图）——教训：视觉路由必须配图像冒烟测试。

**结论**：延迟大头 = TTFT(0.5~1s) + 输出 token 数 ÷ 速度。限长 150 字后各模型差距缩到 1~2s，被口头确认覆盖后用户无感。维持 qwen3.7-flash（同 key 零接入、极便宜）；若 M4 实测拖体验，**最快逃生门是 gpt-4.1-mini（OpenAI 兼容协议，换 base_url + key 即可）**。

## 附：OpenAI Realtime 接入实录（2026-08-16，经 CometAPI 中转）

**背景**：OpenAI 官方不支持香港付款 → 中转站路线。调研结论：gpt-realtime-2.1 发布仅 10 天，
仅 CometAPI 上架（XAI Router / TheRouter 只有 1.5，GetGoAPI 是 SEO 假页面）。

**协议实测发现**（已固化在 provider.py 注释）：
1. **扁平 vs 嵌套 session schema**：官方新"统一接口"用嵌套（session.type + audio.input/output），
   但经典 `/v1/realtime`（中转站透传的）要扁平 GA schema（modalities/voice/input_audio_format…），
   嵌套会报 `unknown_parameter: session.type`。我们 Provider 两族事件名都映射。
2. **工具 schema 需拆包**：Realtime 要扁平 `{type, name, ...}`，HTTP 风格 `{type, function:{...}}` 报 missing name。
3. **模型可用性**（CometAPI，当日）：2.1-mini ✅ / gpt-realtime ✅ / 2、1.5、mini 上游拨号全挂。
4. **通道漂移**：同一模型 10 分钟内从可用变为全通道 "price not configured"——
   **中转实时通道稳定性差，实证了"中转只能用于测试"的判断**。
5. 2.1-mini 的工具调用意愿极强（问时间主动调 bash/web_search，且多工具自主串联）。
   遗留问题：工具结果写回后模型疑似未看到结果而重复调用，待通道恢复后排查。

**OpenAI 官方直连差异备忘**：官方 key 已验证可连通（余额不足未测对话）；
GA 模型禁止携带 `OpenAI-Beta: realtime=v1` 头（new-api PR #6032）。
