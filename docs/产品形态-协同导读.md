# 产品形态：协同导读（Guided Co-reading）

> 状态：概念定稿中。本文是产品的核心交互范式定义，架构设计以此为准。

## 一句话定义

**语音是 AI 的嘴和手指，UI 是共享桌面。** AI 带着用户一块一块地走内容——边走边指、边标记、边生成带索引的实时笔记；用户可以随时打断、提问、跳回、动手改。像两个人真的坐在一起工作，而不是"下任务 → 等结果"的异步交付。

## 与传统 AI 汇报的对比

| | 传统 AI（异步交付） | 本产品（同步协作） |
|---|---|---|
| 交互 | 下任务 → 长时间跑 → 交付一堵文字墙 | 边说边展示，一块一块推进 |
| 用户角色 | 读者（被动） | 协作者（随时打断/提问/修改） |
| 结果载体 | 聊天记录 | **会话文档**：卡片 + 标记 + 索引笔记，可回溯可编辑 |
| 适用场景 | 批量生产 | 教学、知识问答、资料调研、协同阅读 |

## 核心设计原则

### 1. UI 必须可寻址（machine-addressable UI）

屏幕上每个卡片、段落、文字块都有稳定 ID，模型可通过工具调用精确引用（`block_id` / 文字区间）。这是"AI 用手指给你看"成立的前提。

### 2. 工具调用分两类

- **取数工具**：web 搜索、看图（后端快速 VL 模型）、查资料库 —— 拿回内容
- **操控工具**（本产品独有）：`show_card` / `highlight(block_id, range)` / `move_pointer` / `add_note(anchor_id)` / `bookmark(index_id)` —— 操作共享工作区

### 3. 双通道各司其职

- **语音通道**（低带宽、线性、易逝）：叙述、解释、引导、对话
- **视觉通道**（高带宽、空间化、持久）：卡片、文字、标记、笔记
- 两者通过**同步指针**绑定：说到哪，指到哪

### 4. 实时笔记即会话资产

- 模型边讲边生成结构化笔记，带**索引标记**（anchor）
- 用户可按索引回溯（点击索引 → 回放对应片段/定位对应卡片）、查看、修改
- 会话结束，笔记落盘——这就是调研场景的最终交付物

### 5. 特化在外壳，不在模型

模型只负责：听懂 + 会说话 + 会调工具。教学感、协作感全部来自外壳的 UI 指令集与交互设计。模型选型（qwen-audio-3.0-realtime plus/flash）不受此影响，保持可替换。

## 待验证的技术点

- [ ] **音画对齐**：高亮需与语音进度同步。查 Qwen realtime 的 transcript 事件是否带词级/句级时间戳；若无，用音频帧时序近似对齐
- [ ] **打断时的 UI 一致性**：barge-in 发生时，未播完的语音对应的 UI 指令要一并撤销/冻结
- [x] 后端 VL 模型选型（看图工具用）：**已定为 `qwen3.7-flash`**（近旗舰质量、¥0.2/¥0.8 每百万 token、支持 FC/结构化输出/视频）；复杂图表类疑难图升级到 `qwen3.7-plus`。详见调研文档

## 里程碑（粗）
